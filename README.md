# カドカルチョ

選択したチーム同士の試合を観戦する、Pygame製の3Dサッカーシミュレーションです。
この版は「まず1試合を最初から最後まで遊べる」ことに絞ったプロトタイプです。

起動直後のデバッグ選択画面で、ホームとアウェイに読み込むチームをそれぞれ指定できます。

## 現在の仕様

- `teams` フォルダから選択したJSONチーム同士の11対11
- 参考画像をハーフコートとして換算した2200×1420のコート
- 3D座標と透視投影による奥行きのある試合画面
- 16:9を維持した960×540／1280×720／1600×900／1920×1080の画面サイズ切替と全画面表示
- ボールを滑らかに追うデッドゾーン付き追従カメラ
- 基準速度では実時間1秒につき試合時間10秒進行（90分は実時間9分、ハーフタイムあり）
- パス、浮き球、ジャンプ、ドリブル、ボール奪取、シュート、GKセーブ、得点をシミュレーション
- 枠外、ポスト、キーパーが取りやすいコース、バー上に分かれたシュートミス
- 各チームJSONのポジションX／ポジションYによる15×10マス配置
- JSONの5段階戦術・指示なし・ランダム戦術とゾーン範囲による選手AI
- シュート力・シュート精度・パス精度・パス力によるキック性能差
- 最大値・回復速度・管理・疲労耐性による選手ごとのスタミナ性能差
- ミス、ドリブル、トラップ、パスカット、GK、シュート、パス、スティールの8種類のテクニック能力
- 高さ・正確さ・速さ・判断力を分離したジャンプと、強さ・正確さ・判断力を持つヘディング
- 遠距離や相手越しで打ち上げるパス、高さを狙うシュート弾道
- スライディング、立ちヘッド、飛び込みヘッド、転倒の選手モーション
- フィジカル衝突、ドリブル中の身体の使い方、反則、カード、歩いてくる審判
- 11種類のプレイヤータイプと、守備5・攻撃7種類の行動傾向による個性
- `インテリジェンス`による軽量ユーティリティAIの判断精度
- 選手JSONで保有する40種類のスキルと、発動・成功を分離した判定
- 自信、戦術への忠実さ、警戒度、ゾーン・ポジション意識、積極性の動的変化
- GKによるペナルティーエリア内の予測移動・積極回収と、キャッチ、パンチング、足元トラップ、スロー、ショートパス、ロングキックの選択
- 非保持ボールの緩やかな自然減速
- 四角形パーツと「| |」の目で構成した選手モデル
- スローイン、フリーキック、PK、ゴールキック、コーナーキックによる再開
- ホーム／中立地／アウェーと、メンタルによるアウェー能力低下の軽減
- ボール連動の横スライド、個別ローミング、斜めのサポートラン、複数プレス
- シュート数、支配率、試合イベントを表示
- キックオフ前の0:00に、先発能力・役割構成・GK・戦術・監督・会場・控え層から解析した勝利／引き分け／敗北確率を表示（仮想試合なし）

## 初期オリジナルリーグ

- `kadoka_original_A`：20クラブ。J1／N1相当の上位リーグで、新規クラブの総合カテゴリ平均は主に690〜840
- `kadoka_original_B`：20クラブ。J2／N2相当の下位リーグで、総合カテゴリ平均はおよそ490〜640
- Aの既存5クラブは維持し、ACT・WCC級の突出した強豪も上位リーグ内に残す
- B最上位でもA最下位より能力平均が低くなるよう調整し、昇降格後もリーグ差が分かる構成

各新規クラブは16人編成で、役割別能力、監督、戦術、フォーメーション、少数のスキルを持ちます。`leagues.json`ではAリーグにAの20クラブ、BリーグにBの20クラブを配置し、Bの上位リーグをAに設定しています。付属クラブを同じ基準で再生成する場合は`generate_original_league_teams.py`を使用します。

## 起動方法

Windowsでは `run_game.bat` をダブルクリックしてください。

コマンドから起動する場合：

```text
py -m pip install -r requirements.txt
py main.py
```

## ファイル構成

- `main.py`：ゲームを起動するだけのエントリーポイント
- `game_app.py`：Pygameの初期化、入力、チーム選択、カメラ、メインループ
- `rendering.py`：3D投影、コート・選手・UIの描画
- `match_engine.py`：AI、パス、シュート、得点、試合時間などの試合進行
- `entities.py`：Player、Team、Ballのデータと個別動作
- `player_commands.py`：AIが選択できる行動・移動・技術コマンド
- `stamina_system.py`：コマンド別の消費量、回復、疲労補正
- `technique_system.py`：ミス補正、5種類のトラップ、トラップ成功率
- `jump_system.py`：最高到達点、到達時間、予測誤差、ヘディング速度と誤差
- `physical_system.py`：フィジカル判定、会場補正、反則とカード確率
- `intelligence_system.py`：行動効用、判断ノイズ、スライディングとヘッドのリスク評価
- `player_style_system.py`：プレイヤータイプ、守備・攻撃行動値、旧タイプの変換
- `skill_system.py`：スキル名、専用コマンド、発動率、再使用間隔
- `team_data.py`：チームJSONの検証、変換、自動検出
- `team_editor_data.py`：エディタ用テンプレート、検証、自動修正、保存、削除、フォーメーション割当
- `team_editor.py`：チーム・選手・スキル・フォーメーションを編集するPygame画面
- `settings.py`：画面・コート・戦術・カメラの設定値と共通関数
- `teams/`：チームと選手のJSONデータ

## 操作

| キー | 操作 |
|---|---|
| Q / E | チーム選択画面でホームチームを変更 |
| A / D | チーム選択画面でアウェイチームを変更 |
| V | チーム選択画面でホーム／中立地／アウェーを変更 |
| Enter / Space | 選択した対戦を開始 |
| Space | 試合開始／一時停止／再開 |
| Esc | 試合中にポーズ画面を開く／閉じる（再開・中断・残りをスキップ） |
| F | 試合速度を1倍→2倍→3倍→5倍→10倍→100倍の順に変更 |
| F10 | 画面サイズを960×540→1280×720→1600×900→1920×1080の順に変更 |
| F11 | 全画面表示／ウィンドウ表示を切り替え |
| - / [ | 試合画面をズームアウト |
| + / ] | 試合画面をズームイン |
| P / Tab | 選手一覧と試合中パラメーターを表示／閉じる |
| O | リーグ戦の観戦中に、同日開催の「他の試合」速報を表示／閉じる |
| R | 試合終了後に再戦 |
| T | 一時停止中または試合終了後にチーム選択へ戻る |
| Esc | チーム選択画面ではゲームを終了 |

右側の速度ボタンはマウスでも操作できます。試合中は右パネルの−／＋ボタンまたはマウスホイールでもズームでき、倍率を変えてもカメラはボールを追従します。Escのポーズ画面では試合への復帰、試合の中断、残り時間の高速処理を選べます。リーグ観戦をスキップした場合は、観戦試合を完走した後、同日開催の他会場も同じAI・物理演算で高速完了してリーグ画面へ戻ります。チーム選択画面と右パネルの「画面」「全画面」ボタンでも表示を変更できます。内部描画と入力座標は1280×720を基準にし、全画面の解像度が16:9でない場合も余白を付けて比率を維持するため、UI配置と当たり判定は変わりません。右パネル下部のボタンからも選手一覧を開けます。一覧には両チームの先発11人について、スタミナ、忠実度、自信、ゾーン意識、ポジション意識、積極性、現在最も警戒している相手を表示します。上部の表示切替ボタンで、キック・速度・スタミナ・テクニック・ジャンプ・メンタル・インテリジェンス・守備行動・攻撃行動のS〜Eランクも確認できます。閲覧中は試合が停止します。浮き球に対するジャンプは選手AIが自動的に判断します。

## チームエディタ

チーム選択画面左下の`チームエディタ`から開きます。既存の有効・無効なJSONを一覧化するため、試合に読み込めない途中データも開いて修正できます。

- `チーム情報`：名前、略称、監督、カラー、ホームコート、戦術、ゾーン、チーム忠実さ、保存フォルダを編集
- `選手能力`：選手追加・削除、名前、ID、背番号、年齢、性別、プレイヤータイプ、個人忠実さ、51能力を編集
- `スキル一覧`：現在の40スキルをチェックボックスで個別選択。全選択・全解除も可能
- `フォーメーション`：15×10マスへ選手を配置。GKは中央固定の専用枠。3-5-2、4-4-2、4-3-3、4-5-1、5-4-1、4-2-3-1を収録
- `チューナー`：カテゴリ別基準値、選手単体／チーム全体の自動調整、複数対戦相手を使った時間制限付きヘッドレス試合を実行
- `エラー`：必要キー、値の範囲、重複ID・背番号、先発人数、GK人数、FW、配置重複、未登録スキルを確認

保存はエラーが残っていても可能です。JSONファイル名はチーム名から自動生成されるため、既存チームの名前を変更して保存するとファイル名も同時に変わります。`保存フォルダ`には`teams`からの相対フォルダ（例：`Aリーグ/関東`）を指定でき、存在しないフォルダは保存時に作成され、既存チームもその場所へ移動します。空欄なら`teams`直下へ保存します。同名ファイルが既にある場合は上書きせず連番を付け、リーグ設定・進行中のリーグ・リーグセーブ内のチーム参照も新しい相対パスへ引き継ぎます。チームJSONはサブフォルダを含めて自動検出されます。

エラーが解消するまで試合チーム一覧には出ません。`自動修正`は不足キーや範囲外値を有効なランダム値で補い、必要なら11人・GK・背番号・4-4-2配置も整えます。正常な既存フォーメーションは、能力値だけを修正する際には維持されます。数値欄はクリック後にキーボードで直接入力でき、右側の`^`／`v`ボタンはクリックまたは長押しで増減します。選択中はキーボードの↑／↓でも1ずつ変更できます。

新規作成では次のテンプレートを選べます。

- `初期値`：選手1〜11、全51能力を100、4-4-2
- `ランダム`：全能力を50〜1250からランダム生成
- `基準値`：目標平均50〜1250と誤差（小・中・大）を指定して生成

フォーメーションテンプレートは現在位置と各配置先の距離を比較し、近い選手から割り当てます。余った選手は控えになります。既存チームの削除は同じ削除ボタンを2回押す確認式で、最後の試合可能チームは削除できません。文字欄はクリックして入力し、`Ctrl+A`で現在値を消去できます。

### チームチューナー

基準値はキック、スピード、スタミナ、フィジカル、テクニック、ジャンプ、メンタル、インテリジェンス、守備行動（裏）、攻撃行動（裏）の10カテゴリへ個別指定します。自動調整ではカテゴリ平均を基準値の近くへ合わせつつ、ポジションとプレイヤータイプに適した能力へ比重を移します。裏能力の調整はON/OFF可能です。設定は各チームJSONの`チームチューナー`へ保存されます。

能力平均のランクは1000以上がS、800以上がA、600以上がB、400以上がC、200以上がD、200未満がEです。チューナー画面上部には現在の表示・調整対象（選手単体／チーム全体）を表示します。選手単体では選択選手、チーム全体ではチーム平均の数値とランクを大きく表示し、選手を切り替えると表示も即座に切り替わります。対象切り替えだけでは能力値を変更せず、専用の自動調整ボタンを押した時だけ基準値へ調整します。ヘッドレス試合によるチューニングは常にチーム全体が対象です。

試合チューニングでは、対戦相手をチーム一覧から複数選択し、1〜600秒の時間上限を設定します。各候補は選択した全対戦相手とホーム・アウェーの両方を同一乱数条件で戦い、その総合点で比較します。各試合を別のCPUコアへ割り当て、必要な全試合が90分まで完走してから候補を採否判定します。途中試合は進捗表示には使いますが、能力の採用や収束判定には使いません。通常の試合AIと判定を画面なしの高速時計で反復し、得失点、勝敗、シュート、支配率、スタミナ、選手の行動種類と活動率を評価します。完走候補の改善が一定回数止まると収束として終了します。CPUコア数を自動取得し最大8プロセスで並列評価するため、エディタ画面は応答を保ち、中止も可能です。

終了条件は「時間上限」と「収束まで」から選択できます。「収束まで」では秒数設定を使用せず、完走候補の改善が規定回数止まるまで処理を続けます。強いチームなどで長時間探索したい場合に利用でき、実行中も「シミュレーションを中止」からいつでも停止できます。収束モードの進捗バーは、時間ではなく改善なし候補数の収束度を表します。

試合チューニング開始時に、キック・スピード・スタミナなど各分野の現在平均を能力予算として固定します。候補生成と採用結果は開始時平均の±10以内に制限され、平均700の分野が710を超えて強化されたり690未満へ低下したりしません。制約されるのは系統全体の平均だけです。同じ系統内では選手間・能力項目間でポイントを移せるため、平均900を保ったままシュート力1100・シュート精度700のような偏った配分も、総合試合結果が良ければ採用されます。明示的な「選択中の対象を基準値へ自動調整」ボタンだけは、設定した基準値へ平均を変更します。

エディタのテンプレートと選択項目は`teameditor_templete/editor_options.json`、チューナーのカテゴリ・ランク境界・初期時間・高速化設定は`teameditor_templete/tuner_defaults.json`からエディタを開くたびに読み込みます。項目の追加や並び替えはこのJSONで行えます。

## 追従カメラ

通常速度では、ボールが画面内の安定領域から外れたときだけカメラが動きます。追従速度と加速度には上限があり、細かなボールの動きやパスのたびに画面が振動しないよう補間されます。

参考画像はセンターラインからゴールまでのハーフコートとして扱い、その約2倍をピッチ全長にしています。中央付近の選手高約22〜25px、ボール径約6〜8px、センターサークル横幅約190pxを目安に、通常画角では半面が画面へ収まるようにしています。選手モデルは頭、胴、手足、影、背番号を従来描画の72%へ縮小し、選手同士の接触、タックル、ボール取得、ヘディング、GKの手の届く範囲も同じ倍率へ縮小しています。ジャンプで選んだ最高到達位置そのものは変わりません。

倍速が高いほどカメラのデッドゾーンを広げ、画角を滑らかに引きます。特に100倍速ではコートの大部分を表示し、ボールの高速な往復をカメラが直接追い回さないようにしています。

## JSONの日本語キー

`teams`フォルダの選手データは日本語キーを正式な編集形式として使用します。従来の英語キーも読み込めるため、以前作成したチームとの互換性は維持されます。同じ項目へ日本語と英語の両方が書かれている場合は日本語側を優先します。

全項目と選手1人分の記述例は [JSONキー一覧.md](JSONキー一覧.md) を参照してください。

## JSONポジション

- `ポジションX`：左から1〜15。15列の各マス中央へ均等配置
- `ポジションY`：1が最前列、10が自陣側の最終列
- Y=1〜3：FW
- Y=4〜7：MF
- Y=8〜10：DF
- Y=11：GK。Xの値にかかわらずゴール中央へ固定
- Y=0：控え。試合開始メンバーには含めない

先発選手のJSON配置はキックオフ時の初期位置だけでなく、試合中に戻ろうとする基本ポジションにも使用されます。

`チーム情報` 内の `チームの略称` は、スコアボード、試合データ、得点表示、最終結果に使用されます。未設定の場合はチーム名の先頭3文字を使用します。

## キック系ステータス

選手JSONでは50〜1250の値で、次の4項目を指定します。

- `シュート力`（シュート力）：シュートの初速
- `シュート精度`（シュート精度）：狙った位置からのずれにくさ
- `パス精度`（パス精度）：味方へ出すパスの方向のずれにくさ
- `パス力`（パス力）：選択できるパス距離、パス速度、ロングパスの高さ

強いパスは到達が速く、相手が触れてもコントロールしにくいため、結果としてパスカットされにくくなります。既存チームは従来の `キック` の値を4項目へコピー済みです。

## 速度系ステータス

選手JSONでは50〜1250の値で、次の4項目を指定します。

- `ダッシュ時のスピード`（ダッシュ速度）：ダッシュコマンド中の移動速度
- `ウォーク時のスピード`（ウォーク速度）：ウォークコマンド中の移動速度
- `ドリブル時のスピード`（ドリブル速度）：ボールを保持して運ぶ際の移動速度
- `キックモーションのスピード`（キックモーション速度）：パス、シュート、クリアで足がボールへ届くまでの速さ

既存チームでは従来の `スピード` の値を4項目へコピー済みです。キックは即時発生せず、構え、バックスイング、振り抜き、ボールとの接触、フォロースルーの順に進みます。能力1000では接触まで約0.27秒、能力100では約0.72秒です。キック前にボールを奪われた場合はモーションがキャンセルされます。

速度は低能力側をより遅くする非線形カーブです。能力100と1000を比較すると、基準速度はダッシュ約4.06倍、ウォーク約3.44倍、ドリブル約3.93倍の差になります。

## スタミナ系ステータス

選手JSONでは50〜1250の値で、次の4項目を指定します。

- `スタミナ最大値`（スタミナ最大値）：試合中に使えるスタミナの総量
- `スタミナ回復速度`（スタミナ回復速度）：待機・ポジション維持・ウォークなどでの回復速度
- `スタミナ管理`（スタミナ管理）：残量が少ないときに激しい行動を控える判断力
- `疲労耐性`（疲労耐性）：残量低下時の能力低下とミス増加を抑える力

スタミナは移動速度そのものではなく、実行中のコマンドに応じて消費します。ダッシュ、ドリブル、プレス、キック、ヘディング、スライディングなどは大きく消費し、待機や陣形維持では少量回復します。ウォーク中も待機時の45%の速度で回復します。

残量が最大値の1/2を下回ると疲労の影響が始まり、1/3、1/4、1/6、0へ近づくにつれて移動、キック、パス、シュート、ボール処理、守備成功率が低下し、狙いの誤差も増えます。疲労耐性が高い選手はこの悪化が緩やかです。

スタミナが0になるとダッシュ、スライディング、ヘディングを行えません。ただし温存のためにボールやパス受けを放棄することはなく、必要な位置へウォークで向かいます。スタミナ管理が高い選手は、早めにパスを出し、ダッシュドリブルや負担の大きいスキルを控えることで消費を抑えます。現在のボール保持者の残量は、行動コマンドの下の色付きバーで確認できます。

## テクニック系ステータス

選手JSONでは50〜1250の値で、次の8項目を指定します。

- `ミスの少なさ`（ミスの少なさ）：パス、シュート、トラップ、守備、GKの判断ミスを減らす
- `ドリブルの上手さ`（ドリブルの上手さ）：ドリブルやボールキープ中に奪われにくくする
- `トラップの上手さ`（トラップの上手さ）：強いボールや高いボールを収めやすくする
- `パスカットの上手さ`（パスカットの上手さ）：パスコースへ反応する範囲と、相手パスを奪う成功率を高める
- `ゴールストップ力`（ゴールストップ力）：GK時のシュート軌道予測とセーブ率を高める
- `シュートの上手さ`（シュートの上手さ）：狙う場所、距離、強さ、弾道、カーブの判断を良くする
- `パスの上手さ`（パスの上手さ）：味方とコースの選択、距離、強さ、浮き球、カーブの判断を良くする
- `スティールの上手さ`（スティールの上手さ）：ドリブル、キープ、トラップ中の相手から奪いやすくする

旧 `テクニック` の値は8項目へ同値で移行済みです。トラップはボールの高さと進入方向から右足、左足、右膝、左膝、胸を選び、成功時の収まり位置と失敗時のこぼれる方向がそれぞれ異なります。球速が高いほど難しく、パスカットではパスカット能力とトラップ能力の両方を使用します。

シュートとパスでは「何を選ぶか」と「正確に実行できるか」を分離しています。シュート技術・パス技術が弾道や強さを選び、実際の方向と高さのずれはシュート精度・パス精度で決まります。

## ジャンプ・ヘディング系ステータス

選手JSONでは50〜1250の値で、次の7項目を指定します。

- `ジャンプの高さ`（ジャンプの高さ）：選べる最高到達点を高くする
- `ジャンプの正確さ`（ジャンプの正確さ）：判断した位置・高さ・タイミングからの実行ずれを減らす
- `ジャンプの速さ`（ジャンプの速さ）：選んだ最高到達点へ短時間で到達する
- `ジャンプの判断力`（ジャンプの判断力）：ボールの到達位置、高さ、時間を正しく予測する
- `ヘディングの強さ`（ヘディングの強さ）：ヘディングで出せる球速と飛距離を上げる
- `ヘディングの正確さ`（ヘディングの正確さ）：狙った方向と高さへのずれを減らす
- `ヘディングの判断力`（ヘディングの判断力）：シュートまたは迎撃時の狙いと力加減を良くする

旧 `ジャンプ` の値は7項目へ同値で移行済みです。ジャンプの最高到達点は能力50で18、能力1250で92ワールド単位、最高点へ届く時間は能力50で約0.64秒、能力1250で約0.24秒です。高さと速さは独立しているため、高く跳べる選手と素早く最高点へ届く選手を別々に作れます。

ジャンプ判断ではボールの速度、落下、高さから将来位置を予測します。その読みにはジャンプ判断力だけでなく、味方パスの受けならトラップ、相手パスならパスカット、フィールド選手のシュートカットならパスカット、GKのシュート対応ならゴールストップ力も使用します。

ヘディングは、敵ゴール前で味方の浮き球をシュートする場合と、自陣側で相手の浮き球・シュートを迎撃する場合だけ選びます。通常の味方パスは足、膝、胸のトラップを優先し、ボール保持中にヘディングへ移行することはありません。迎撃ヘッドは各チーム1人だけが反応し、連続使用にも判断間隔があります。

`プレイヤータイプ`には次の11種類を指定します。タイプは行動候補を禁止するものではなく、ユーティリティAIがどの行動を選びやすいかを大きく変える指針です。

| ストッパー | マンツーマンと強いプレス |
| マンマーカー | マンツーマンとインターセプト |

| オールラウンド | マンツーマンと保持者のサポート |
| ダイナモ | オーバーラップ、マーク外し、スペースへの走り込み |

## 試合中に変化するパラメーター

- `自信`（自信）：JSONでは50〜1250。高いほどシュート、前進、フェイント、スキルなど大胆なプレーを選びやすい
- `戦術への忠実さ`（戦術への忠実さ）：JSONでは0〜100。試合開始時の忠実度で、ゾーン、基本ポジション、個人が選んだ戦術をどの程度徹底するかを決める
- 警戒度：各選手が相手選手11人それぞれへ持つ値。保持者、ゴールに近い選手、能力と自信が高い選手ほど強く警戒する
- 忠実度：点差と残り時間で開始値から変化する。低いほど戦術を完全には守らず柔軟に動く
- ゾーン意識／ポジション意識：忠実度、インテリジェンス、積極性、試合状況から変化し、陣形へ戻る強さとボール連動の度合いを決める
- 積極性：全員0.5から開始し、プレイヤータイプ、自信、個人戦術、点差から変化する。高いほど前後左右の移動範囲が広がる

自信は得点、失点、ボール奪取、GKのセーブなどでも上下します。スタミナ低下は通常能力とミスへ影響しますが、`インテリジェンス`だけは低下しません。

## インテリジェンス

`インテリジェンス`は50〜1250で指定する選手AIの賢さです。既存55選手には従来の`メンタル`と同じ値を初期値として設定済みです。

AIは、シュート、パス、ドリブルなどの候補へ状況別の効用を付けて比較する軽量なユーティリティ方式を使います。インテリジェンスが高いほど、距離、空き、前進量、相手の圧力、反則リスクを正確に評価し、低い選手ほど評価に大きな判断ノイズが入ります。パス先、パスカットの予測地点、セットプレーの狙い、ヘディングの用途、スライディングを選ぶかにも反映されます。候補はピッチ上の現在状態だけを1段階評価するため、重い経路探索や深い先読みは行いません。

相手が110以内まで近づくと保持者は判断間隔を短縮し、パス、シュート、通常ドリブル、保有スキルを再評価します。守備側は常に最寄りの選手が寄せ、通常は最低2人、自陣の危険地帯では最低3人がプレス候補になります。相手ゴールラインから72以内では前進し続けず、中央への切り返し、折り返しパス、またはシュートを選びます。

現在のユーティリティAIは学習済みモデルではなく、試合状態から毎回効用を計算する方式です。そのため学習工程や学習データは不要で、チームJSONを追加した直後から同じ判断規則で試合できます。

## GKのボール処理

GKはボールの速度、高さ、シュートの読みにくさ、自分のゴールストップ力、トラップ能力、自信から、キャッチ、パンチング、足元トラップ、GK専用スキルをユーティリティAIで比較します。速く高いボールはパンチング、遅い低球はキャッチやトラップを選びやすく、判断の適切さは`インテリジェンス`に依存します。

選手が保持していないボールは、地上では毎秒約12%、空中では毎秒約1.5%ずつ速度を失います。低速になってから停止するため、こぼれ球やパンチングが急に止まらず自然に転がります。

## パス・シュート弾道

遠くの味方へ出すほど高いパスを選びやすくなります。パスコース上に相手がいる場合は、相手までの距離と必要なクリア高さを計算し、頭上を越す打ち上げパスを選びます。判断にはパスの上手さ、実際の高さのずれにはパス精度を使用します。

シュートは固定の低い垂直初速ではなく、ゴールへ届く時刻と狙った高さから必要な垂直初速を逆算します。通常、ロング、カーブ、ループで目標の高さと追加する山なり成分が異なります。

## スライディング・ヘディングモーション

通常のボール奪取は接触直前の立ったタックルを使います。スライディングは最も近い守備選手だけが、通常タックルより離れた位置から、接触タイミング、スティール能力、相手のボール保持力、ゴールの危険度、反則リスクを比較して十分に有利な場合だけ選び、実行後は再使用まで間隔があります。奪取直後の滑走中キックは、スキル保有者の得点機におけるスライドフィニッシュ、または相手が目前にいる緊急パスに限定します。

タックルで保持者がボールを落とした場合、ボールは倒れた選手と一緒に遠くへ飛ばず接触地点付近へ残ります。タックル側の近い2人は1.25秒間だけ優先してこぼれ球へ走り、取得範囲と収球率に小さな補正を受けます。所有権を自動付与するものではないため、相手が先に触れればそのまま相手が回収できます。

その場でのヘディングは、立った姿勢のまま上体と頭をボール方向へ振ります。離れた接触地点へ飛び込む場合は身体を横にした飛び込みヘッドになり、着地後は倒れてから復帰します。

## フィジカル・メンタル・セットプレー

選手JSONでは50〜1250の値で、`衝突時のフィジカル`（衝突時の強さ）、`ドリブル時のフィジカル`（ドリブル中の身体の強さ）、`フィジカルプレイの質`（身体の使い方）、`メンタル`、`安全なプレー`、`フリーキック`、`ペナルティキック`、`ゴールキック`、`スローイン`、`コーナーキック`を指定します。旧`フィジカル`は3種類のフィジカル能力へ移行済みです。

通常の選手同士の接触は重なりだけを解消し、吹き飛びモーションは発生しません。どちらかが実際にタックル／スライディングコマンドを実行中の接触だけ能力と勢いを比較し、負けた側をボールから遠ざけます。同じ2人の接触には連続判定防止時間があり、弾かれた選手が保持者ならその場でボールを離します。ドリブル中はドリブル時のフィジカルとプレイの質が高いほど相手を身体でブロックし、スティールされる隙と不必要な回避移動が減ります。

各チームの`チーム情報`には`ホームコート`があります。チーム選択画面でHOMEのホーム、AWAYのホーム、中立地を選択でき、相手のホームでは全能力が低下します。`メンタル`が高いほどこの低下を抑えます。

危険なスライディングには反則判定があり、`安全なプレー`が高いほどファウルとカードを抑えます。反則時は審判が接触地点まで歩き、必要ならイエロー／レッドカードを提示します。2枚目のイエローとレッドでは退場し、選手一覧にも表示されます。

## 場外と試合再開

タッチラインを越えると、最後に触った側の相手チームのスローインです。`スローイン`が高いほど空いていて前進できる味方を選び、一定以上ならロングスローを使えます。

ゴールラインを越えた場合、守備側が最後に触れていればコーナーキック、攻撃側ならゴールキックになります。コーナーでは戦術が攻撃的なほど多くの味方がゴール前へ入り、守備側も戦術に応じた人数でゴール前を固めます。両チームとも全員は集まらず、攻撃側はカウンター対策、守備側はカウンターの受け手を中央付近に残します。守備側が奪った直後は、選手のインテリジェンスやパス判断などに応じて中央の味方を狙ったクリアやGKのパンチングを選ぶことがあります。ゴールキックは`ゴールキック`で安全な味方を選びます。反則地点がペナルティエリア内ならPK、それ以外はフリーキックです。セットプレー能力は判断に使い、実際の球威と精度は既存のシュート／パス能力を使います。

## チーム戦術とゾーン

`チーム情報` から次の項目を読み込みます。

- `戦術`：超攻撃的／攻撃的／バランス／防御的／超防御的／指示なし／ランダム
- `ゾーン手前`：1〜10
- `ゾーン奥`：1〜10
- `戦術への忠実さ`：チーム全体の忠実さ。0〜100で、高いほど共通戦術を徹底し、低いほど選手の判断を許して柔軟に動く

通常の5戦術は移動速度、プレスの開始位置と強度、前方パス、ドリブル、シュート距離、攻守の切り替えへ影響します。`指示なし`では各選手が点差、残り時間、役割、自信を評価し、自分に合う通常戦術を選び直します。`ランダム`では選手ごとに通常戦術を無作為に選び、選び直す時間も異なるためチームのまとまりが崩れます。

チーム情報の忠実さと選手個人の忠実さは別々に保持し、両方をAIへ反映します。選手個人の項目が省略された場合だけ、チーム値を初期値として継承します。これは能力値ではないため、高いほど常に有利ではありません。高いチーム・選手は指示の再現性が高く、低いチーム・選手は陣形やゾーンから外れる余地が増えます。

選手は指定ポジションを基準にしつつ、役割、個人戦術、現在の忠実度と積極性に応じた個別ローミングを行います。忠実度が低い選手ほど戦術の極端な指示を弱め、状況へ柔軟に対応します。FWとMFは横方向や斜め方向のサポートランが大きく、DFは形を残しながらボール側へスライドします。

## 監督システム

監督名が設定されたチームでは、監督AIがスコア、残り時間、シュート数、支配率、ボール位置、各選手のスタミナと控え選手の能力を観察します。監督が決断した内容はすぐには反映されず、次のセットプレー、スローイン、または得点後に実行されます。

- `戦術変更への積極性`：戦況を確認する頻度と、小さな変化でも戦術を変える傾向。50〜1250
- `選手交代への積極性`：どの程度の疲労・能力差で交代へ踏み切るか。50〜1250
- `インテリジェンス`：情報の重み付け、戦術選択、交代候補選択の正確さ。50〜1250
- 交代は1試合3人まで。退場選手は交代できず、交代済み選手は戻れません
- 積極性は高ければ常に有利ではありません。高すぎる監督は短期的な揺れへ反応しやすく、低すぎる監督は必要な変更が遅れます
- 監督名が空欄の場合は監督AIが働きません。控えがいない場合は戦術変更だけを行います

試合中の選手一覧には現在戦術と交代人数を表示し、変更の予約と実行は試合イベントにも表示します。チームエディタでは3つの監督能力を編集してJSONへ保存できます。

## 選手AIコマンド

選手AIは、目標座標へ直接移動するだけでなく、次に何をするかをコマンドとして保持します。コマンドは「行動」「移動」「技術」「スキル」の4層を同時に持てます。

- 行動：パス、スルーパス、クロス、シュート、クリア、ドリブル、ボールキープ、プレス、マーク、カバー、パスカット、シュートカット、ポジション復帰、ボール追従、サポート、パスコース作成、オーバーラップなど
- 移動：待機、ウォーク、ダッシュ
- 技術：キック、スライディング、ヘディング、トラップ、セーブなど
- スキル：保有スキルから状況とインテリジェンスに応じて選ばれる専用コマンド

各コマンドには優先度と最低継続時間があります。シュートやトラップなどの重要な動作が、直後の低優先度なポジション復帰で上書きされないようになっています。ボール保持者の名前と現在の行動コマンドは試合画面上に表示されます。

同じ選手が狭い範囲でボールを保持し続けた場合は「保持停滞」として検出します。近距離サポートの価値は固定人数ではなく、その候補地点にいる味方、そこへ移動中の味方、パスコースを作成中の味方を含めた限界効用で決まります。空いていれば複数人のサポートも高く評価されますが、担当者が増えるほど追加サポートの価値が下がり、元の横幅、前後のレーン、斜めのパスコース、裏のスペースへ行く価値が上がります。空きスペース、パスの受け手、マーク対象も同じ担当重複の考え方で評価します。守備側は第一プレッサーだけが保持者へ直接向かい、後続のプレッサーは左右から囲んでパスコースを塞ぎます。

ゾーン1は自陣ゴール側、ゾーン10は敵陣ゴール側です。GKを除く選手は手前〜奥の範囲へ配置されます。ボールが手前より自陣側へ移動するとチーム全体が守備へ戻り、奥より敵陣側へ移動するとチーム全体が押し上がります。アウェイチームでは攻撃方向に合わせて座標を反転します。

## AIパラメータ評価

`run_ai_evaluator.bat`は通常の試合と同じ`Match`を画面なしで実行し、指定した能力値だけを変えたチームを同じ対戦相手・同じ乱数シードで比較します。画面、カメラ、描画待ちは作成しません。試合時計だけを飛ばすこともせず、物理、AI、モーション、ボール、試合時計を共通の0.05秒固定ステップで進めます。

何も指定しなければ、先頭チームのインテリジェンス50・650・1250を各2試合、15分相当ずつ評価します。90分を完走する場合や処理上限を変更する場合は次のように実行します。

```text
run_ai_evaluator.bat --team "夕張kadoka japan" --opponent "私立蜜柑山学園" --parameter インテリジェンス --values 50,650,1250 --matches 4 --full-match --wall-seconds 0 --processes auto
```

- `--matches`：各値の試合数。ホーム・アウェーを交互にします
- `--game-minutes`：短時間評価の試合内時間。既定は15分
- `--full-match`：90分を完走
- `--wall-seconds`：1試合が使用できる実時間。0は無制限
- `--processes`：同時プロセス数。既定は安全な1、`auto`で自動取得
- `--max-processes`：自動取得時も超えないプロセス上限。既定は8

結果は`ai_evaluation`へJSONとCSVで保存します。得失点、シュート、支配率、残スタミナ、行動種類、活動率、コマンド別回数、味方との平均距離、密集率、チーム幅、ボールとの平均距離、奪取・喪失を記録します。JSONには実行ステップ数、試合内時間、実時間、完走状況、CPU数、実際に使ったプロセス数も残るため、AI改善と処理上限の両方を比較できます。

チームチューナーも同じ固定ステップへ統一しました。従来の20倍時計では90分表示でも実際のAI判断が約20分の1しか実行されなかったため、時計だけの加速は廃止しています。初期実装では90分に約3分半かかり、旧ワーカー上限90秒では精度重視が毎回途中終了していました。プロファイル後、オフボール戦術を物理と同じ毎秒20回再計算していた部分を分離しました。移動、衝突、ボールは20Hzのまま、戦術再判断はインテリジェンスに応じて約3〜7Hzです。同一ステップの陣形、サポート順位、疲労補正、会場補正、戦術設定も再利用し、同じ90分10800ステップを実測約43秒まで短縮しました。複数試合の同時実行ではCPU競合により長くなるため、1試合上限300秒と精度重視の時間上限最低600秒は安全余裕として維持しています。

対戦相手を複数選んだ場合、最初の候補で全相手とのホーム・アウェーを偵察します。得失点、シュート差、支配率から「格上（差が大きい）」「勝てそうな格上」「互角」「僅差で勝っている」「優勢」「大幅優勢」に分類し、僅差で負けている相手を最優先、互角と僅差勝ちを次点として評価ウェイトを自動設定します。大勝できる相手や現状では差が大きすぎる相手も完全には無視しません。

チューナー画面で`精度重視`と`速度重視`を切り替えられ、既定は精度重視です。精度重視は2候補目以降も選択した全相手のホーム・アウェーを90分まで毎回完走し、分類は評価倍率だけに使います。速度重視は時計だけを飛ばさず通常物理の5分評価区間を使い、2候補目以降をウェイト上位3チームへ絞ります。支配率、シュート、行動種類、活動率、スタミナなどを進行率で補正して粗く比較するため、精度は90分評価より下がります。相手一覧には倍率、分類、精度重視なら`全評価`、速度重視なら`重点`または`予備`を表示します。速度重視の相手数は`tuner_defaults.json`の`adaptive_opponent_limit`、評価時間は`speed_evaluation_minutes`で変更できます。

収束判定は相手数に比例させません。候補1件の中ですでに全対象試合を比較しているため、既定では意味のある改善が4候補連続で見つからなければ収束です。スコア差0.10未満の微差は改善としてカウンタを戻さず、速度重視は乱数的な小改善で永久に続かないよう最大16候補で終了します。進捗バーは現在の候補内で終了した評価数を表示し、状態欄には`現在の候補 4/6評価完了`のように表示します。

## デバッグ用チーム選択

- 起動時に `teams` フォルダの有効な `.json` を自動検出
- ホーム・アウェイを別々に選択可能
- 同じJSONチーム同士の対戦も可能
- 両チームのユニフォーム色が同じ場合、アウェイ側は識別用の青色になる
- 空ファイルまたは仕様を満たさないJSONは選択肢から除外
- JSONを追加・変更した場合はゲームを再起動すると候補へ反映

以前の内蔵チーム定義は廃止済みで、すべての選択候補を `teams` フォルダのJSONから読み込みます。

## リーグ戦

チーム選択画面の「リーグ戦」から、`leagues.json`の各リーグが保有するチーム同士の年間リーグを進行できます。各組み合わせはホームとアウェーで1回ずつ行われ、同じ節の試合は同日開催です。

- 進行対象のリーグは複数選択可能
- 「1日進める」または「次の試合までスキップ」で日付を進行
- 観戦予約した試合は通常の試合画面で観戦
- 予約しなかった試合も、通常と同じ90分・選手AI・ボール・反則・セットプレーを画面なしで実行。同日試合は複数CPUコアで並列処理
- 使用ワーカー数は論理CPUから物理コア相当を推定し、同時試合数と空き物理メモリから自動決定。非観戦日は推定物理コアをすべて結果計算へ使い、観戦日はpygame・描画用に1コア残す。大きなCPUでも最大8試合、空きメモリ約1.5GBを確保し、1ワーカー約320MBとして安全側に制限。残りは待ち行列で順次実行し、画面に全試合数・同時数・推定巡数を表示
- 画面なし試合も通常試合と同じ20Hzの物理・AI判定を使用。遠距離の選手ペアを平方根計算前に除外し、発動中のスキル待ち時間だけを更新し、同一ステップの得点緊急度・戦術・疲労補正を再利用することで、判定を簡略化せず高速化
- 観戦中は右パネルの「他の試合」またはOキーから、同日開催の別試合の経過時間とスコアをリアルタイム表示
- 同日試合は開始時点と物理演算の進行ペースだけを揃え、試合時計は会場ごとに独立。ある会場のスローイン・フリーキック準備によって別会場や観戦試合が停止することはない。観戦試合終了後はペース制限を解除し、未終了の同日試合を通常と同じ物理・AI判定のまま全速で完走してからリーグ結果画面へ移動
- 別試合は観戦試合と同じ試合時計までだけ進行。停止時は一緒に停止し、倍速時も先に90分まで処理されない。CPU側が遅れた場合は観戦時計を短時間待たせて同期を維持
- 観戦終了時には、選択中の別リーグを含む同日全試合も確定
- 成績は勝利3点、引き分け1点、敗戦0点。勝点、得失点差、総得点、勝利数の順で順位を決定
- 「リーグ戦編集」でリーグ名、追加（最大999リーグ）、削除、上位リーグ、所属チーム、生成済み試合日を編集。大会一覧はマウスホイールとスクロールバーで移動
- チーム配置は`teams`内の保存フォルダ別に見出しと配置数を表示。配置欄へマウスを置いたホイール操作または右端のスクロールバーで、チーム数にかかわらず全クラブを確認・配置可能
- 「トーナメント編集」でノックアウト大会を作成。参加元リーグは複数選択でき、全所属チームまたは各リーグ前年上位Nチームを統合して参加。各ラウンドは前ラウンド後の最短の空き日へ進み、リーグ戦の開催日は自動回避。同点はPK戦で決着
- レギュラーシーズン終了後、上位リーグ下位1・2チームと下位リーグ1・2位が12月第2土曜日に入れ替え戦を実施
- 下位リーグ側が入れ替え戦に勝つと両チームの所属を交換。引き分けはPK戦で決着
- 年と日付、日程、結果、観戦予約、前年以前の順位表と全試合結果は`league_save/*.json`へ保存
- セーブ画面では複数のリーグ戦を新規作成・途中再開・削除可能。削除は同じボタンを2回押す確認式
- 壊れたJSON、存在しないチームを参照するセーブはエラー内容を表示し、修正されるまで再開しない

旧版の`league_state.json`がある場合は、元ファイルを残したまま初回起動時に`league_save/自動セーブ.json`へコピーします。リーグ画面の「途中保存」でいつでも明示保存でき、通常の日付進行や試合確定時にも自動保存されます。成績画面ではyearボタンで前年以前の最終順位表を切り替えられます。セーブデータは読みやすい通常のJSONで、暗号化していません。

チームJSONには所属リーグを保存しません。`leagues.json`の各項目が`所属チーム`配列を持ち、`json:ファイル名.json`形式のチームIDを保有します。同じチームを複数リーグへ追加でき、★印が優先リーグです。試合日が重なった場合は優先リーグの日程を残し、他リーグの試合を空き日へ移します。「優先」ボタンで優先先を変更できます。チーム配置を変えるとホーム＆アウェーの日程を自動で組み直します。

リーグ名、トーナメント名、セーブ名、チームエディタの文字欄はpygameのIME確定入力と変換中文字表示に対応しています。日本語変換中の文字は入力欄へ仮表示され、確定時に一度だけJSONへ反映されます。

日程作成後は「試合日程編集」で未消化試合を1日または7日単位で移動できます。終了済み試合と、12月第2土曜日固定の入れ替え戦は変更できません。リーグ名・リーグ数・チーム配置・上下関係の変更は開幕前のみ可能です。

`leagues.json`の`上位リーグ`が上下関係です。空文字のリーグが最上位です。昇格・降格後の所属は各リーグセーブ内の`league_memberships`に記録されるため、基本配置や別のセーブには影響しません。
