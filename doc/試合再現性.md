# 試合再現性（段階的な導入）

## seedの入口

`Match(home_choice, away_choice, venue_mode, *, seed=整数)` は、選手・チームの生成より前に試合専用の乱数器を初期化する。同じチームデータ、設定、seed、固定ステップ入力から新しい `Match` を作れば、初期状態と試合進行を再現できる。`seed=None` は従来どおり非決定的で、試合テスト等の既存呼び出しを維持する。

試合層の乱数は `match.rng` を使い、プロセス共通の `random.seed()` は変更しない。同じ試合オブジェクトで `start_new()` を繰り返すことは再現契約の対象外であり、再生時には新しい `Match` を生成する。

## リーグ・評価

リーグの観戦試合と裏試合は、`league_fixture_seed()` で同じseedを計算する。既存の裏試合の算出式（`fixture_id:home_name:away_name` のUTF-8 SHA-256先頭8バイト）を保つ。ただし、これまでは選手生成後にseedを設定していたため、選手の初期乱数値と試合結果は変わり得る。評価ツールとチューナーも、各試合生成時に既存のfixture seedを注入する。

## 描画あり・なしの検証

`python -m scripts.tools.match_repro_check` は、同じチーム・seedを使うヘッドレス試合とPygame描画試合を別々に実行する。固定ステップ数、得点、選手位置・スタミナ・行動、ボール、イベント、試合時計、乱数状態を比較し、結果をJSONとして標準出力へ出す。描画にはダミーSDLとCPU描画を使い、実際の `Game.draw()` を呼ぶ。比較中は画面を表示しない。

既定では最大18,000ステップで90分の完走を要求する。短い確認には `--max-steps 300 --allow-partial` を使える。`--seed`、`--home`、`--away`、`--render-every` も指定可能。試合中のイベントは現在 `Match.events` が保持する範囲を比較するもので、全履歴を保存する仕組みではない。

## 入力条件の保存と再実行

`--save-input <JSONパス>` は、比較を始める前に両チームの開始時データと計算条件をUTF-8で保存する。出力先の親フォルダは先に作成する。既存ファイルは上書きしない。開発ログの保存先にはGit管理外の `user_data/logs/` を使う。

```text
python -m scripts.tools.match_repro_check --seed 12345 --venue NEUTRAL --save-input user_data/logs/match-input.json
python -m scripts.tools.match_repro_check --load-input user_data/logs/match-input.json
```

形式は `format: kadocalcio.match-repro-input` / `version: 1`。`teams.home` / `teams.away` はチームID・選手能力・監督・戦術等を含む正規化済み入力の複製で、元チームファイルの編集・移動・削除に依存しない。通常のチーム編集用JSONやリーグセーブとは別形式とし、小数の能力値も丸めない。`settings` は `seed`、`venue_mode`、`ai_rethink_multiplier`（0.5〜3.0）、`fixed_physics_dt`（0.05）、`max_steps` を保持する。

`--load-input` 時は記録したチームと設定を両経路に渡す。`--home` / `--away` / `--seed` / `--max-steps` / `--venue` / `--ai-rethink-multiplier` の同時指定は受け付けない。描画間隔 `--render-every` と未完走を許す `--allow-partial` は選択できる。描画には通常の `Game.draw()` を利用するため、スタジアム等のアセットとPygameは必要。

`commands` は空配列を記録する。version 1は外部操作なしの自律試合が対象で、空でないCommand列や未対応の形式バージョン・固定ステップを読み飛ばさず拒否する。同じエンジン実装・設定定数・Python環境での再実行用であり、将来のAI・物理変更前の挙動を保存するエンジンアーカイブではない。
