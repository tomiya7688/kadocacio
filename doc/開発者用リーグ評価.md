# 開発者用リーグ評価

## すぐに8時間動かす

`run_developer_evaluation.bat`をダブルクリックします。標準テンプレート内で2チーム以上所属する全リーグを対象に、画面なしの精密モードで8時間評価します。

ランチャー本体は`cmd.exe`がコードページ設定前でも確実に解釈できるASCII命令だけで構成し、Pythonの標準入出力をUTF-8へ固定しています。バッチへ引数を渡した場合は既定の8時間設定に代わってその引数を使用するため、`run_developer_evaluation.bat --list-templates`で短い起動確認もできます。

通常のリーグセーブは変更しません。ログは実行ごとに`development_evaluation/league_eval_日時/`へ分離して保存します。

## コマンド指定

```bat
.venv\Scripts\python.exe -m scripts.tools.developer_league_evaluator --hours 8 --leagues all --processes auto
```

主な指定は次のとおりです。

- `--hours 8`: 今回の実時間上限です。0なら時間では終了しません。実行中の試合日は最後まで処理してから終了します。
- `--seasons 3`: 3年度完走で終了します。0なら年度数では終了しません。
- `--template default`: 使用するリーグテンプレートIDです。`--list-templates`で一覧表示できます。
- `--leagues "Aリーグ,Bリーグ"`: 対象リーグを限定します。`all`は有効な全リーグです。
- `--quality PRECISE`: `ULTRA_PRECISE`、`PRECISE`、`NORMAL`、`LIGHT`からAI判断頻度を選びます。
- `--cpu-limit 50`: CPU演算予算を10～100%で指定します。OSの厳密な使用率制限ではなく、ワーカー数と各ワーカーの休止時間を調整します。
- `--processes auto`: CPU数と空きメモリから同時試合数を決めます。
- `--max-processes 8`: 自動取得時にも超えない安全上限です。
- `--max-matchdays 1`: 動作確認用に処理する試合日数を制限します。0なら無制限です。
- `--stop-on-error`: 1試合でも例外が出た時点で直ちに終了します。省略時も未完走試合は順位表へ入れず、その試合日を未処理のまま安全に終了します。

時間と年度数を両方0にすると、Ctrl+Cで止めるまで継続します。

## 中断と再開

各試合日の完了後に`checkpoint.json`を原子的に更新します。Ctrl+C、Windows終了、異常終了後は次のように再開できます。

```bat
.venv\Scripts\python.exe -m scripts.tools.developer_league_evaluator --resume "development_evaluation\league_eval_20260827_090000" --hours 4
```

`--resume`にはログフォルダまたは`checkpoint.json`を指定できます。`--hours`は再開した今回の実行時間です。品質、CPU上限、プロセス数も再開時に上書きできます。

## 保存されるログ

- `config.json`: 実行条件
- `checkpoint.json`: リーグ状態、完了試合日数、完了年度数を含む再開データ
- `matches.jsonl`: 全試合のスコア、シュート、支配時間、残スタミナ、AIコマンド、密集率、チーム幅、奪取・喪失、実行時間、固定ステップ数
- `seasons.jsonl`: 各年度のリーグ最終順位と昇格・降格結果
- `events.jsonl`: 開始、各試合日の開始・完了時刻
- `errors.jsonl`: ワーカー例外とトレースバック、再試行後も未完走だった試合の終了理由・試合時間・停止中セットプレー
- `summary.json`: 全体集計、速度の平均・95%点・最大値、失敗数、チーム別集計
- `team_summary.csv`: チーム別の勝敗、得失点、シュート、支配率、残スタミナ、密集率など
- `commands.csv`: チーム別AIコマンド使用回数
- `performance.csv`: 試合別の実時間、固定ステップ数、完走・失敗状態

`matches.jsonl`は一試合ごと、`events.jsonl`は一試合日ごとに追記するため、最後の集計前に停止しても途中までの観測結果は残ります。

## 試合判定

評価は通常試合と同じ`Match`、0.05秒固定ステップ、AI、ボール、反則、スタミナ、監督処理を使用します。描画と待ち時間だけを省き、簡易勝敗式や時計だけの早送りは使いません。

固定ステップの安全上限へ達した試合は、上限を2倍にして一度だけ同じ条件で再試行します。それでも90分を完走しなければ途中スコアを`matches.jsonl`や順位表へ入れず、セットプレー種別と停止時間を`errors.jsonl`へ記録して評価を終了します。チェックポイントから再開すれば、その試合日は未処理の状態から再実行されます。

AIテレメトリは評価ジョブでだけ有効です。通常プレイや通常のリーグ裏試合には、コマンド・密集度サンプリングの追加負荷は入りません。
