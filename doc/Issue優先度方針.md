# Issue優先度方針

優先度は作業順の判断であり、機能の価値・作業量・依存待ちの長さとは別。P0は緊急対応のために基本的に空けておく。

| 優先度 | 意味 | 目安 |
|---|---|---|
| P0 | 緊急対応専用 | 現在発生している起動不能、データ破損/消失、重大な安全性問題、主要操作を完全に止める障害。通常計画を止めて復旧が必要な場合のみ。 |
| P1 | 優先して進める | 現在の重点方針であるGodot移行、重要な設計改善など。重要でも緊急障害でなければこちら。 |
| P2 | 通常 | 通常の改善・機能追加・開発者ツール整備。未指定時の既定値。 |
| P3 | 後回しでもよい | 利便性・見た目・追加最適化など、しばらく待っても支障が小さい項目。 |
| P4 | 将来予定 | 現段階の実装計画外の新しい遊び方、別モード、長期構想。削除や拒否の意味ではない。 |

## GitHubでの扱い

- 一つのIssueに `P0`～`P4` のラベルを一つ付ける。ラベルが正本。タイトルに `[P1]` 等を残す場合は同じ値に揃える。
- 古いIssueのタイトル表記も読み込む。ラベルとタイトルが違えばラベルを優先。両方なければP2として扱う。
- P0を付ける場合は「現在の障害・影響・緊急に復旧する理由」を本文に記す。`bug` は不具合分類であり、P0の必須条件でも十分条件でもない。
- 大規模リファクタをP0にしない。依存待ちのP1を、その理由だけでP4にしない。将来機能で現在の工程外ならP4にする。
- `tracking` / `blocked` / `in-review` は進捗・依存状態であり、優先度を変更しない。レビュー待ちはIssueを閉じずin-reviewへ置く。
- 既存の完了Issueは履歴なので書き換えない。open Issueの方針整理は優先度ラベル/必要なタイトル表記だけを変更し、本文・依存関係・状態は保持する。

## 自動選択

`start_task.bat` は除外ラベルを持たないopen Issueから、以下の順に一件を選ぶ。

1. P0→P1→P2→P3→P4。
2. 同じ優先度なら `task_selection.json` の `preferred_labels`（現在はgodot-migration）に一致するもの。
3. さらに同じならIssue番号が小さいもの。

低優先度の移行Issueが高優先度の通常Issueを追い越さない。明示番号はこの並びを迂回するが、依存待ちを無視する許可ではない。

旧 `task_selection.json` の `urgent_labels` は読み込み互換のため受け付けるが、選択順には使わない。P0はカテゴリに依存せず最優先。
