# 宣言コメント規約

正本は [Json-like-comment-outs 日本語仕様](https://github.com/tomiya7688/Json-like-comment-outs/blob/5691767a8708407a568a75a242543a4add825253/docs/jp/SPECIFICATION.md)（Draft v0.9）。このプロジェクトでは日本語キーを使う。

- クラスの宣言直前に `責務`・`フィールド`。主要状態の意味と責任範囲を書く。状態を持たない場合は `フィールド: []`。
- 関数・メソッド・入れ子関数の宣言直前に `責務`・`処理`・`引数`・`戻り値`。処理は意味のある単位を実行順に記す。副作用と失敗条件は必要な項目内で説明する。
- Pythonはデコレータより前、GDScriptは `class_name` より前。クラス名を持たないスクリプトは `extends` の前にクラス相当の説明を書く。
- 各項目は別の行に `キー: [説明]` と書き、全体を `{` と `}` で囲む。長い配列は複数行にする。JSONとして有効である必要はない。
- 引数なしは `引数: []`。暗黙の `self`・`cls` は省略してよい。戻り値なしも `戻り値: [None: …]` / `戻り値: [void: …]` と、副作用や終了条件を説明する。
- コードの逐語訳や空テンプレートではなく、目的・理由・状態の意味を書く。内部の通常コメントに構造形式は不要。
- 追加ファイルの全宣言と、既存ファイルの追加・変更宣言を必ず確認する。変更されたクラスも責務・主要フィールドを更新する。未変更の巨大ファイル全体への一括ダミー説明は行わない。
- PRがgreenでも、この説明が無いものは差し戻し。差し戻し済み・閉じられたPRも修正対象とし、コメント修正前に再提出しない。

```python
# {
#   責務: [read: 外部入力を検証して独立した状態へ復元する]
#   処理: [1: 必須項目を検証; 2: 正常な値だけを複製する]
#   引数: [payload: 外部JSON値]
#   戻り値: [dict: 独立した状態。不正な入力はValueError]
# }
def read(payload):
    ...
```

## 構造確認とレビュー

```powershell
.venv\Scripts\python.exe -m scripts.tools.static_analysis.json_like_comments --base <実際のPRのbase> --head <提出head>
.venv\Scripts\python.exe -m scripts.tools.static_analysis.json_like_comments scripts/core/match_operation.py
```

不足は終了コード1、読込・対象エラーは2。`--output user_data/logs/comment_review/report.json` で位置・宣言名・不足項目を残せる。変更前後の宣言構造を比較するため、コメントだけの変更や依存PRの不変宣言は差分対象に含まれない。初回には各PRの実際のbaseとheadで検査し、必要なら個別ファイルの全宣言も確認する。

このツールはPython ASTとGDScriptの宣言範囲による**最低構造検査**。説明の正確さ・処理順・読みやすさ、完全なコメントDSL構文、すべてのGDScript構文を認定するものではない。人が本文と実装を照合し、通常の構文検査・試験も実行する。既存PRの不足を隠すための自動ダミーコメント挿入機能は持たない。
